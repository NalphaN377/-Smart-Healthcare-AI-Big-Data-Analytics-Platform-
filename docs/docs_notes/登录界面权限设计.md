# 智慧医疗平台 — 登录界面与权限设计

## 1. 用户角色概览

| 角色 | 标识 | 典型使用者 | 核心场景 |
|---|---|---|---|
| 患者用户 | `patient` | 就诊患者、家属 | 了解疾病趋势、健康科普、查询自身相关问题 |
| 医生用户 | `doctor` | 临床医生、科室主任、数据分析员 | 深度数据分析、疾病研究、报告生成 |
| 运维员用户 | `admin` | 系统管理员、数据工程师 | 数据导入、系统监控、用户管理 |

---

## 2. 各角色权限明细

### 2.1 患者用户（`patient`）

当前平台存储的是 **SPARCS 脱敏聚合数据**，不包含个人可识别信息，因此患者不能查看"自己的病历"。患者角色的定位是 **健康信息消费者**。

| 模块 | 权限 | 说明 |
|---|---|---|
| 运营总览 | ✅ 查看 | 聚合级指标（住院量、平均住院日、费用概览），不含敏感明细 |
| AI 智能分析 | ✅ 使用 | 通用健康趋势、疾病科普类问题，AI 回复限定为科普参考 |
| 数据资产 | ❌ 不可见 | 不暴露数据导入链路、质量评估等运维信息 |
| 患者画像 | ❌ 不可见 | 不暴露其他患者群体的聚合数据 |
| 分析报告 | ⚠️ 受限 | 仅可查看已发布的公开报告，不可生成新报告 |
| 数据导出 | ❌ 不可用 | 不允许导出任何数据 |

**AI 问答限制**：患者角色使用独立的 system prompt，并在 AI 调用分析工具前限制为公开疾病、年份和服务区域维度；不得仅依靠 prompt 控制权限。人数少于 11 的聚合分组不向患者返回。

---

### 2.2 医生用户（`doctor`）

医生角色是平台的 **核心分析用户**，拥有完整的数据分析能力。

| 模块 | 权限 | 说明 |
|---|---|---|
| 运营总览 | ✅ 完整访问 | 全部 KPI 指标、趋势图表、AI 洞察 |
| AI 智能分析 | ✅ 完整使用 | 深度查询、流式问答、多维度分析 |
| 数据资产 | ✅ 查看 | 数据接入状态、质量评估、处理链路 |
| 患者画像 | ✅ 完整访问 | 年龄结构、性别分布、疾病分组、严重程度 |
| 分析报告 | ✅ 生成+导出 | 在线生成 Markdown 报告并下载 |
| 数据导出 | ✅ 可用 | 导出仪表盘数据为 JSON |
| 数据导入 | ❌ 不可用 | 不涉及数据运维 |
| 用户管理 | ❌ 不可用 | 不涉及账号管理 |
| 系统配置 | ❌ 不可用 | 不涉及功能开关和系统参数 |

---

### 2.3 运维员用户（`admin`）

运维员角色是平台的 **最高权限管理者**，负责数据运维和系统管理。

| 模块 | 权限 | 说明 |
|---|---|---|
| 运营总览 | ✅ 完整访问 | 同医生 |
| AI 智能分析 | ✅ 完整使用 | 同医生 |
| 数据资产 | ✅ 完整访问 + 管理 | 数据导入、清洗任务管理、质量评估监控 |
| 患者画像 | ✅ 完整访问 | 同医生 |
| 分析报告 | ✅ 生成+导出 | 同医生 |
| 数据导出 | ✅ 可用 | 同医生 |
| 数据导入 | ✅ 可用 | 触发全量/增量导入，查看导入审计日志 |
| 用户管理 | ✅ 可用 | 创建/禁用/删除账号，重置密码，修改角色 |
| 系统配置 | ✅ 可用 | 管理功能开关（feature flags）、查看服务健康状态 |
| 系统日志 | ✅ 可用 | 查看 API 调用记录和异常日志 |

## 4. 登录界面设计建议

### 4.1 页面布局

```
┌──────────────────────────────────────────────┐
│                                              │
│          🏥 智医数析                          │
│     SMART HEALTHCARE PLATFORM                │
│                                              │
│     ┌─────────────────────────────┐          │
│     │  用户名                      │          │
│     │  ┌───────────────────────┐  │          │
│     │  │                       │  │          │
│     │  └───────────────────────┘  │          │
│     │  密码                        │          │
│     │  ┌───────────────────────┐  │          │
│     │  │                       │  │          │
│     │  └───────────────────────┘  │          │
│     │                             │          │
│     │  ┌───────────────────────┐  │          │
│     │  │      登  录            │  │          │
│     │  └───────────────────────┘  │          │
│     └─────────────────────────────┘          │
│                                              │
│        没有账户？去注册                        │
│        忘记密码？请联系管理员                  │
│                                              │
└──────────────────────────────────────────────┘
```

### 4.2 交互流程

1. 用户访问平台 → 检测未登录 → 跳转登录页
2. 输入用户名 + 密码 → 后端验证
3. 验证通过 → 获取用户角色 → 按角色加载对应菜单和权限
4. 验证失败 → 显示错误提示（不区分"用户名不存在"和"密码错误"）
5. 登录成功后 → 患者进运营总览 / 医生进运营总览 / 运维员进数据资产
6. 患者或医生点击“去注册” → 填写账户资料并完成注册 → 返回登录页

### 4.3 安全要求

- 密码使用 `bcrypt` 或 `werkzeug.security` 哈希存储，不可明文
- 登录失败 5 次后临时锁定账号 15 分钟
- 使用服务端 Session；Cookie 设置 `HttpOnly`、`SameSite=Lax`，生产环境设置 `Secure`
- Session 绝对有效期 8 小时，默认空闲 60 分钟自动退出
- 非安全方法使用 CSRF Token 校验，登录成功后重建 Session
- 敏感操作（数据导入、用户管理）需二次确认

## 5. 数据库表设计（草案）

### users 表

```sql
CREATE TABLE dbo.users (
    id BIGINT IDENTITY(1,1) NOT NULL CONSTRAINT pk_users PRIMARY KEY,
    username NVARCHAR(50) NOT NULL CONSTRAINT uq_users_username UNIQUE,
    password_hash NVARCHAR(255) NOT NULL,
    display_name NVARCHAR(100) NULL,
    role NVARCHAR(20) NOT NULL CONSTRAINT ck_users_role CHECK (role IN ('patient', 'doctor', 'admin')),
    email NVARCHAR(200) NULL,
    is_active BIT NOT NULL DEFAULT 1,
    failed_login_attempts TINYINT NOT NULL DEFAULT 0,
    locked_until DATETIME2(0) NULL,
    last_login_at DATETIME2(0) NULL,
    created_at DATETIME2(0) NOT NULL DEFAULT SYSUTCDATETIME(),
    updated_at DATETIME2(0) NOT NULL DEFAULT SYSUTCDATETIME()
);
```

### 预置账号

| 用户名 | 角色 | 说明 |
|---|---|---|
| `admin` | admin | 运维员初始账号，首次登录后强制修改密码 |
| `doctor_demo` | doctor | 医生演示账号 |
| `patient_demo` | patient | 患者演示账号 |

演示账号仅允许在开发/演示环境按需创建。生产环境只通过交互式脚本创建初始管理员，不在源码或 SQL 中保存固定密码。

## 6. 后端 API 设计

| 方法 | 路径 | 功能 | 权限 |
|---|---|---|---|
| POST | `/api/auth/login` | 用户登录，建立服务端 Session | 公开 |
| POST | `/api/auth/register` | 患者或医生注册账户 | 公开 |
| POST | `/api/auth/logout` | 退出登录 | 登录用户 |
| GET | `/api/auth/me` | 获取当前用户信息（角色、权限） | 登录用户 |
| POST | `/api/auth/change-password` | 修改密码 | 登录用户 |
| DELETE | `/api/auth/account` | 注销自己的账号（需验证密码） | patient / doctor |
| GET | `/api/admin/users` | 用户列表 | admin |
| POST | `/api/admin/users` | 创建用户 | admin |
| PUT | `/api/admin/users/<id>` | 修改用户（角色、激活状态） | admin |
| DELETE | `/api/admin/users/<id>` | 删除除自己之外的账号（软删除） | admin |

账号删除和用户自助注销均采用软删除，设置 `is_active=false` 和 `deleted_at`，以保留报告和审计关系。管理员不能删除自己的账号。

补充接口：

| 方法 | 路径 | 功能 | 权限 |
|---|---|---|---|
| GET | `/api/reports/public` | 已发布公开报告 | 登录用户 |
| POST | `/api/admin/users/<id>/reset-password` | 重置密码 | admin |
| PUT | `/api/admin/reports/<id>/publish` | 发布公开报告 | admin |
| GET | `/api/admin/system/health` | 数据库、LLM、功能开关状态 | admin |
| GET | `/api/admin/audit-logs` | 登录及管理操作审计 | admin |

## 7. 前端路由改造

现有单页应用改为按角色路由：

- `/login` — 登录页（公开）
- `/register` — 患者/医生注册页（公开，禁止注册运维员）
- `/account` — 账户设置与注销账号（登录用户；管理员不可自助注销）
- `/overview` — 运营总览（所有角色）
- `/ai` — AI 智能分析（所有角色，患者受限）
- `/data` — 数据资产（医生 + 运维员）
- `/patients` — 患者画像（医生 + 运维员）
- `/reports` — 报告生成与管理（医生 + 运维员）
- `/public-reports` — 已发布公开报告（所有角色，患者为只读）
- `/admin/users` — 用户管理（仅运维员）
- `/admin/system` — 系统配置（仅运维员）

侧边栏菜单根据角色动态渲染，患者看不到"数据资产"、"患者画像"等菜单项。

> 服务端接口权限是安全边界；动态菜单和前端路由守卫不替代后端鉴权。
